# Sawwerna — frontend

React 18 + Vite + Tailwind v4 SPA for [sawwerna.com](https://sawwerna.com). An
event-based disposable camera: a host creates an event, guests join by QR and shoot
from their own browser, and the album reveals at a time the host picks.

The API lives in `../sawwerna-be` and answers at `http://localhost:2169` in dev
(`src/config/config.js`'s `DEVELOPMENT` flag) and `https://api.sawwerna.com` in
production.

## Commands

|                      |                                                  |
| -------------------- | ------------------------------------------------ |
| `npm run dev`        | Vite dev server on `http://localhost:5173`       |
| `npm run build`      | production build into `dist/`                    |
| `npm run preview`    | serve the production build locally               |
| `npm run lint`       | ESLint (flat config, `eslint.config.js`)         |
| `npm run cf:preview` | build, then run it on Cloudflare's local runtime |
| `npm run deploy`     | build and deploy the assets-only Worker          |

There is no test suite in this package.

## SEO and brand assets

`index.html` is the only HTML a crawler or a link-preview scraper is ever served —
the app is client-rendered, so the title, description, Open Graph card and
structured data in that file all describe the **landing page**. Per-screen titles are
applied after mount by `src/hooks/useSeo.hook.js`, which defaults every screen to
`noindex`: the landing page is the only public one, and everything under `/events`,
`/account` and `/share` is somebody's private album. `public/robots.txt` says the
same thing to crawlers that never run the bundle.

Everything in `public/` below is generated from `public/logo.png` — the favicon set,
the PWA icons and the 1200×630 social card:

```
favicon.svg  favicon.ico  apple-touch-icon.png  icon-192.png  icon-512.png
icon-maskable-512.png  og-image.jpg
```

They are generated by scripts that need `sharp` and `@napi-rs/canvas`, which only
the backend has installed; regenerate them by running them from `../sawwerna-be`.
The two favicons come from `node scripts/gen-favicon.mjs` there.

**The favicon is the wordmark alone** — no plate behind it, trimmed to the glyphs
and drawn flush to the left and right edges of the square, which is the largest a
2:1 mark can be in a 1:1 slot. `favicon.svg` is the one that follows the viewer's
theme, black on light and white on dark, because an `.ico` or a `.png` carries
fixed pixels and cannot: it holds both colours as two images and lets a
`prefers-color-scheme` query pick one. It is listed first in `index.html` so any
browser that understands it prefers it; `favicon.ico` is framed identically but is
black-only, and is reached only by browsers that ignore the SVG. The PWA and
Apple touch icons are deliberately **not** transparent — iOS composites those onto
black and Android onto its own surface, so they keep their plate.

The hero (`uncached-hero-app.webp` / `uncached-hero-app-800.webp`) is a local, optimised copy of what used
to be hot-linked from Framer's CDN — it is the landing page's LCP element, so it is
preloaded in `index.html` and must stay in step with the `srcset` in
`src/pages/Main/Landing/components/Main.section.jsx`.

After a deploy that changes any of this, re-submit `https://sawwerna.com/sitemap.xml`
in Google Search Console and re-scrape the card with Facebook's Sharing Debugger —
both cache aggressively.
